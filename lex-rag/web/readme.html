Как устроена система

Это справочная по законам Узбекистана. Вопрос задают обычными словами, а ответ приходит вместе с текстом статьи и ссылкой на lex.uz.

Главное правило: модель только читает и пишет, а за факты отвечает код.

Путь вопроса

Девять шагов от запроса до ответа. Обычно весь путь занимает 6–7 секунд и стоит примерно 0,2 цента.

  1. Вход

    Запрос идёт через Cloudflare и туннель на сервер. Для API нужен ключ, у сайта свои лимиты: 6 вопросов в минуту с адреса и 300 в день на всех.

    API-ключ, rate limit

  2. Быстрая проверка

    Код определяет язык вопроса. Если такой вопрос уже задавали, сразу отдаёт готовый ответ.

    кэш

  3. Чтение вопроса, около 2 с

    Модель не отвечает, а составляет план: про закон ли это, как сказать это языком закона, какие слова искать, в каком акте смотреть. Вопрос не про закон получает отказ сразу.

    query rewriting

  4. Поиск, около 0,5–1 с

    Код ищет по словам и по смыслу, потом объединяет списки. Утратившие силу и ещё не вступившие акты отсеиваются. Остаётся до 60 кандидатов.

    hybrid search, RRF

  5. Отбор

    Берутся 20 лучших кандидатов вместе с соседними частями их статей, чтобы текст не был вырван из контекста.

    small-to-big retrieval

  6. Ответ, около 3 с

    Модель пишет только по этим источникам, ставит метки и приводит точные цитаты. Если источники вопрос не решают, она должна отказаться.

    grounded generation

  7. Контроль

    Код проверяет, что метки ведут на реальные источники, а числа есть в законе или в самом вопросе. Если нет, одна повторная попытка, потом отказ.

    guardrails

  8. Сборка

    Название акта, статью, статус, дату и ссылку подставляет код, а не модель. Цитата сверяется с текстом закона.

    детерминированные цитаты

  9. Выдача и запись

    Ответ уходит пользователю, копия сохраняется в кэш и в журнал вместе со временем каждого шага и ценой.

    логирование

Языки

  • Кириллица и латиница. Переводит код по таблице букв с правилами, это транслитерация. Ответ модель пишет на латинице, код переводит его в кириллицу.
  • Русский. Отдельного переводчика нет. Модель превращает вопрос в узбекский запрос и пишет ответ сразу по-русски. Цитаты остаются на языке закона.

Хранилища

Отдельных серверов баз данных нет, всё лежит файлами. У каждого файла своя задача: индекс только читается, а базы результатов постоянно пишутся, поэтому пересборка индекса не трогает результаты и журнал.

Почему так

Только узбекская латиница
Меньше данных, кириллица получается кодом, русский вопрос разбирает модель.
Шаг чтения вопроса
Люди пишут не языком закона. С планами поиска статья находилась заметно чаще: 96% против 65% на обычных вопросах.
Гибридный поиск
Слова находят точные термины, векторы находят смысл при других формулировках.
Реквизиты подставляет код
Модель не может выдумать источник.
Отказ вместо догадки
Для законов неверный ответ хуже отсутствия ответа.
SQLite вместо Postgres
Один файл, нет отдельного сервера, поиск FTS5 встроен. Важно на сервере, общем с другим проектом.
Векторы в 8 бит, точный перебор
Индекс занимает 261 МБ, результат всегда одинаковый.
Haiku, а не модель крупнее
Быстрее и дешевле: весь контрольный прогон стоил около 0,16 $.
Cloudflare Tunnel
Порты 80 и 443 заняты другим проектом, а его трогать нельзя.

Ограничения

  • Цель выше 95% не достигнута. Сейчас примерно 82 верных ответа из 99.
  • Отказы. Это главная оставшаяся потеря: 14 раз система отказалась там, где ответ есть. Чаще всего модель не назвала нужный акт.
  • Суммы. Посчитанного числа нет в источнике, поэтому вопросы вроде «15 БРВ в сумах» система не считает.
  • Скорость. Цель 5 секунд для половины ответов пока не достигнута: 6,9–10 секунд. У сервера одно физическое ядро, поэтому поиски идут по очереди.
  • Разные ответы. Модель может ответить по-разному при новом запуске. API не принимает temperature и seed, стабильность даёт только кэш.
  • Дата. as_of_date только убирает ещё не вступившие акты. Старых редакций в базе нет.
  • Что не измерено. Точность цитат и верность источникам (faithfulness) пока не мерены: для этого нужен отдельный судья.
  • PDF. Около 8 600 актов только в PDF в базу не вошли.
