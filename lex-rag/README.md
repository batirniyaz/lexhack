# lex-rag

Учебный проект: система ответов на вопросы по законодательству Узбекистана на данных lex.uz. Требования к API лежат в `RAG API — test spetsifikatsiyasi (lex.uz).pdf`.

## Как отвечает система

Главное правило взято из проекта `uzex`: модель читает и формулирует, а правду держит код.

1. **Чтение вопроса.** Модель переписывает вопрос на языке законов, предлагает термины и вероятные акты. Вопросы не про право отсекаются здесь.
2. **Поиск.** Код ищет словами (BM25 по узбекским основам), по смыслу (векторы) и внутри названных актов, а затем объединяет списки. Индекс актов, потерявших силу, отделён от основного: ошибка ранжирования не может вернуть устаревшую норму.
3. **Ответ.** Модель получает источники под короткими именами `C1`, `C2` и пишет ответ, ссылаясь на них.
4. **Проверка кодом.** Каждая ссылка должна вести на настоящий источник. Каждое число в ответе должно стоять в цитируемом тексте, причём `21` и `yigirma bir` считаются одним значением. Если проверка не прошла, у модели есть одна попытка исправиться, потом ответ становится `no_answer`.
5. **Сборка JSON.** Номера актов, статьи, статусы, даты и цитаты подставляет код из индекса. Модель их не пишет, поэтому выдумать источник не может.

Ещё несколько решений:

- Единица поиска и цитаты: часть статьи, а в актах без статей пункт. Поэтому `article` и `part` в ответе точные.
- Вопрос на кириллице переводится в латиницу кодом, на русском его понимает модель. Ответ на кириллице получается из латиницы кодом.
- `temperature` и `seed` API принимает и ни на что не влияет: Claude API их больше не поддерживает. Повторяемость обеспечивают детерминированный поиск и сохранённые ответы.

## Данные

Берём только узбекскую латиницу. На каждой странице есть ID кириллической и русской версий.

1. `crawl.py list` находит все документы: 55 282, столько же, сколько в статистике сайта.
2. `crawl.py all` скачивает страницы и карточки отменённых актов в `data/raw/`.
3. `crawl.py ru` докачивает русские страницы актов, у которых на узбекском нет текста.
4. `build_parquet.py` разбирает страницы в `data/parquet/`: `acts`, `elements`, `links`.
5. `build_index.py` строит `data/index/lex.sqlite`: акты, чанки и словесный индекс.
6. `embed.py` считает векторы, сначала для самых сильных актов. Его можно прервать в любой момент.

Сырые страницы хранятся всегда, поэтому ошибка парсера исправляется без повторного скачивания.

Чего в базе нет: около 8,6 тысячи документов существуют только в PDF, это почти целиком местные решения. Ещё несколько сотен страниц пусты на всех языках.

`crawl.py all` работает без присмотра:

- пропала сеть: ждёт её и продолжает, сайту это в вину не ставит;
- не отвечает одна страница: пропускает её, она остаётся в очереди на следующий запуск;
- сайт ответил 404 или пустой оболочкой без текста: страница идёт на второй круг, потому что однажды сайт 38 секунд отдавал 404 на все запросы подряд;
- не отвечает весь сайт: ждёт 30 минут и пробует снова, после 8 таких пауз завершается;
- сайт отказывает на всё (403): завершается сразу и сам не возвращается;
- сон: на батарее Windows усыпляет ноутбук примерно через 5 минут после того, как погас экран, и запрет на сон этому не мешает. Закрытая крышка усыпляет всегда. После пробуждения обход продолжается сам.

Сборщик представляется как `lex-rag-edu-crawler`, держит заданную скорость и снижает её при ошибках или заметном замедлении сайта.

## Запуск API

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env                 впиши ANTHROPIC_API_KEY и LEX_API_KEY (и LEX_APP_KEY для своего проекта)
.venv\Scripts\python -m uvicorn api.main:app --port 8000
```

Эндпоинты: `POST /v1/rag/batch`, `GET /v1/rag/batch/{batch_id}`, `POST /v1/rag/query`, `GET /v1/meta`, `GET /v1/health`.

Страницы лежат в `web/`, сделаны по Hallmark, тема Almanac. `/readme` объясняет систему простыми словами; цифры там вписаны вручную, после нового прогона их надо обновить. Главная спрашивает через `POST /api/ask` без ключа, поэтому у неё свои лимиты: 6 вопросов в минуту с адреса и 300 в день на всех, готовые ответы из кэша не считаются (`ASK_PER_MINUTE`, `ASK_PER_DAY` в `api/main.py`).
`/logs` открыта без пароля: ссылок на неё нет, поисковикам она закрыта через `noindex`. Журнал пишется в `data/logs.sqlite`: каждый ответ с сайта, из API и из батча, куда ушло время, цена, план поиска. Адреса посетителей не хранятся. `eval/run_eval.py` в конце прогона отправляет туда свои оценки.

## Сервер

API работает на VM Azure рядом с другим проектом и выходит наружу через Cloudflare Tunnel: порты 80 и 443 заняты, и их конфиг не меняется.
Всё наше лежит в `/opt/lexrag`, службы `lexrag` и `lexrag-tunnel`, порт `127.0.0.1:8100`. Память ограничена, при нехватке первой падает наша служба.

```
bash deploy/deploy.sh                          # код, ключи, перезапуск
bash deploy/upload.sh data/index/lex.sqlite    # большой файл; после обрыва просто запустить ещё раз
bash deploy/upload.sh data/index/vectors.faiss
python scripts/build_starts.py                 # после пересборки индекса: какие акты вступают в силу позже даты принятия
```

Туннель обрывает ответ через 100 секунд, поэтому батч дольше 90 секунд уходит в async: `202`, потом `GET`.

## Проверка

```
.venv\Scripts\python -m pytest tests
.venv\Scripts\python eval\check_gold.py        стоят ли ключевые фразы в ожидаемых статьях
.venv\Scripts\python eval\run_retrieval.py     качество поиска без модели
.venv\Scripts\python eval\run_eval.py          весь сценарий спецификации через работающий API
.venv\Scripts\python scripts\pilot_report.py   качество разбора законов
```

`eval/gold.jsonl`: вопросы с ожидаемой статьёй, написанные своими словами, а не скопированные из закона.

## Условия lex.uz

Сайт разрешает использование только для персональных целей, копирование ради прибыли запрещено без письменного разрешения. Данные лежат в `data/`, в git не попадают и публиковать их нельзя.
